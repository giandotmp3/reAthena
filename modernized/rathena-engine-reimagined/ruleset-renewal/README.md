# ruleset-renewal

Luau package `ruleset.renewal` (architecture sections 6.3, 6.4, 10, 12 M5): the renewal architecture proof. The renewal **basic weapon attack** is implemented and matches the real
legacy renewal code on 8,858 / 8,858 golden cases (and 153,708 / 153,708 fresh-seed fuzz cases). The verdict on "renewal = a data diff plus a few stage overrides" is in
`docs/ARCHITECTURE_PROOF.md`: no engine-core / mods / base change was needed (script-host later gained the pipeline runtime, `num.f32` and `config` for the proof's design findings, see `docs/ARCHITECTURE_PROOF.md` section 12), but the weapon pipeline is **not** mostly a data diff (3 of 24 stages identical, 9 overridden, 10 new, 34 % of the code lines shared).

- `mod.toml`, `package.toml`: manifest (accepted by `mods_tool manifest`/`resolve`, passes the `rathena.base` purity gate) and BR-RULESET-118 config (two bundles; sub-flags are unsupported advanced overrides, off by default).
- `scripts/pipeline.luau`: the renewal stage order (weapon: verified against the stage probes of the real code; magic: from BR-RULESET-044, unverified) and `register(engine)`: `engine.pipeline.define` for both orders, then the weapon stage bodies through `pipeline.stage` (`init` and `final` protected). The engine runs the loop (`pipeline.run`).
- `scripts/damage/`: `weapon.luau` (stage bodies `STAGES.*`, `register`, `calc_attack`: builds the attack state, the prelude (lucky dodge, crit, hit), then `pipeline.run`), `fp.luau` (float32 / double helpers over the host's `num.f32`), `consts.luau`, `unit.luau`. Same `ctx` interface as the pre-renewal package.
- `scripts/formulas.luau`: entry points `res_reduction`, `crit_damage`, `weapon_atk_range` (BR-RULESET-025, 034, 010); the rest raise `NotImplemented` (no golden data).
- `data/`: `pipeline.json`, `tables.json`, `hooks.json`; `damage_tables.luau` (element matrix of `db/re`, size modifiers; generated and cross-checked against the legacy binary) and `damage_cfg.luau` (battle.conf values the pipeline reads, cross-checked likewise).
- `conformance/golden_gen/`: the renewal golden generator (patch of a COPY of the legacy tree, hook, case generator; README there). `conformance/golden/weapon_re.jsonl.gz`: 8,858 recorded cases with every RNG draw and 34 stage probes. `conformance/vectors/`: hand-derived vectors of the pure formulas.
- `docs/`: `ARCHITECTURE_PROOF.md` (the report), `PIPELINE_DIFF.md` + `pipeline_diff.json` (generated by `tools/diff_report.py`), `BR_RULESET_CORRECTIONS.md` (corrected rule text).
- `tests/`: `test_ruleset_renewal.py` (Python wrapper, 53 tests) over the Luau suites (`tests/main.luau`, 111 tests, the figure rathena-sim pins; `tests/extra.luau`, 17 more: move, no-body, effective-order probes, `legacy_quirks`); `tests/support/fake_host.luau` + `booted.luau` stand in for script-host's engine table in the CLI suites; `tools/`: `run_tests.py`, `bundle_luau.py`, `lint_numeric.py`, `build_golden.py`, `diff_report.py`, `mutation_check.py`, `trace_case.sh`.

## Run

    LUAU=<path>/luau python3 -m unittest discover -s tests -v      # 42 pass, 11 expected-failure (Python 3.11+, stdlib only)
    LUAU=<path>/luau python3 -I tools/run_tests.py [--report|--bench]
    LUAU=<path>/luau python3 -I tools/mutation_check.py             # the golden comparison bites: 28 mutants, 0 survive
    python3 -I tools/diff_report.py                                 # regenerate docs/PIPELINE_DIFF.md

The Luau CLI is found through `$LUAU`, `PATH` or `$RATHENA_LUAU_ROOT/{b,build}/luau`; without it the tests that need it are skipped, not passed.

## Pipeline runtime and legacy_quirks (follow-up to the proof)

`register(engine)` hands the 24 weapon stage bodies to script-host's pipeline runtime and `calc_attack` calls `pipeline.run("weapon", S, ...)`, so mods can insert,
replace, cancel and move stages of this package (`script-host/tests/test_rulesets.cpp` does, and replays the 8,858 golden cases through the real runtime).
`cfg.legacy_quirks` (default true, from the manifest through `engine.config`) governs the doubled monster crit multiplier and the `weapon_damage_rate[16]` aliasing:
see the header of `scripts/damage/weapon.luau` and `tests/acceptance/quirks_test.luau`. Details and numbers: `docs/ARCHITECTURE_PROOF.md` section 12.
