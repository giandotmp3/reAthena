# ruleset-renewal

Luau package `ruleset.renewal` (architecture sections 6.3, 6.4, 10, 12 M5): the renewal architecture proof. The renewal **basic weapon attack** is implemented and matches the real
legacy renewal code on 8,858 / 8,858 golden cases (and 153,708 / 153,708 fresh-seed fuzz cases). The verdict on "renewal = a data diff plus a few stage overrides" is in
`docs/ARCHITECTURE_PROOF.md`: no engine-core / mods / base change was needed (script-host later gained the pipeline runtime, `num.f32` and `config` for the proof's design findings, see `docs/ARCHITECTURE_PROOF.md` section 12), but the weapon pipeline is **not** mostly a data diff (3 of 24 stages identical, 9 overridden, 10 new, 34 % of the code lines shared).

- `mod.toml`, `package.toml`: manifest (accepted by `mods_tool manifest`/`resolve`, passes the `rathena.base` purity gate) and BR-RULESET-118 config (two bundles; sub-flags are unsupported advanced overrides, off by default).
- `scripts/pipeline.luau`: the renewal stage order (weapon: verified against the stage probes of the real code; magic: from BR-RULESET-044, unverified) and `register(engine)`: `engine.pipeline.define` for both orders, then the weapon stage bodies through `pipeline.stage` (`init` and `final` protected). The engine runs the loop (`pipeline.run`).
- `scripts/damage/`: `weapon.luau` (stage bodies `STAGES.*`, `register`, `calc_attack`: builds the attack state, the prelude (lucky dodge, crit, hit), then `pipeline.run`), `fp.luau` (float32 / double helpers over the host's `num.f32`), `consts.luau`, `unit.luau`. Same `ctx` interface as the pre-renewal package.
- `scripts/formulas.luau`: entry points `res_reduction`, `crit_damage`, `weapon_atk_range` (BR-RULESET-025, 034, 010); the rest raise `NotImplemented` (no golden data).
- `data/`: `pipeline.json`, `tables.json`, `hooks.json`; `damage_tables.luau` (element matrix of `db/re`, size modifiers; generated and cross-checked against the legacy binary) and `damage_cfg.luau` (battle.conf values the pipeline reads, cross-checked likewise).
- `conformance/golden_gen/`: the renewal golden generator (patch of a COPY of the legacy tree, hook, case generator; README there). `conformance/golden/weapon_re.jsonl.gz`: 8,858 recorded cases with every RNG draw and 34 stage probes. `conformance/vectors/`: hand-derived vectors of the pure formulas.
- `docs/`: `ARCHITECTURE_PROOF.md` (the report), `PIPELINE_DIFF.md` + `pipeline_diff.json` (generated by `tools/diff_report.py`), `BR_RULESET_CORRECTIONS.md` (corrected rule text).
- `tests/`: `test_ruleset_renewal.py` (Python wrapper, 65 tests) over the Luau suites (`tests/main.luau`, 111 tests, the figure rathena-sim pins; `tests/extra.luau`, 104 (17 before the status layer): move, no-body, effective-order probes, `legacy_quirks`); `tests/support/fake_host.luau` + `booted.luau` stand in for script-host's engine table in the CLI suites; `tools/`: `run_tests.py`, `bundle_luau.py`, `lint_numeric.py`, `build_golden.py`, `diff_report.py`, `mutation_check.py`, `trace_case.sh`.

## Status layer (renewal `status_calc_*`, declarative)

`scripts/status/` implements the status effects and the stat aggregation of the renewal ruleset as **data plus a ruleset-supplied ordered stage list per attribute**, and `conformance/` replays it
against the REAL `status_calc_*` functions of the legacy renewal binary (31,470 cases, 85,178 outputs, 100 % match; `docs/ARCHITECTURE_PROOF.md` part 2).

* `scripts/status/status.luau`: `status.define(name, { fields = { val1 = "level", ... }, contributes = { str = { "add", "stat_bonus", when = "...", at = 6798 }, ... }, state_when = {...}, note = ... })`. `at` is the
  `status.cpp` line of the statement (citation and order key); `when` / `value` are expressions of a small C-like integer language (`scripts/status/expr.luau`: int32, truncating `/`, arithmetic `>>`);
  `group` / `rank` express `if (A || B)` and first-present chains. The states, flags and calc flags of a status come from the data record (`data/status_records.luau`, generated from the migrated `db/re` status
  database by `tools/gen_status_records.py`).
* `scripts/status/defs/*.luau`: 321 hand-written definitions (the 317 statuses the renewal `status_calc_*` functions read, parsed from `status.cpp` by `conformance/golden_gen/enum_statuses.py`, plus 4 with only
  conditional restrictions): 658 contributions, each with its `status.cpp` line. `docs/STATUS_FIELDS.md` (generated) names the val1..val4 slots of every covered status (answer to Q-F).
* `scripts/status/attrs_re.luau`: the 48 attributes (41 functions of the hook, `speed_rate`, the fix / rate attributes of the maximum HP / SP / AP) with their ordered stage lists: the fold of engine-core's
  `AttributeSystem` (`attrs.hpp`), written as pure functions `(acc, contributions) -> acc` over contributions `{ source, tag, value }`; `scripts/status/engine_model.luau` is a Luau transcription of the C++
  class and `tests/acceptance/status_model_test.luau` checks that the aggregation runs through it. `aggregate.luau` builds the contribution list (base, unit facts, derived attributes, statuses) and folds it.
* `states.luau` (BR-073: `status_calc_state`), `recalc.luau` (BR-077: calc-flag cascade of `status_calc_bl_main`, the re-entrance guard, the delayed-damage hold), `bonus_scripts.luau` (BR-075: the `Script:` of a
  status compiled to a list of bonus deltas), `u64.luau` (the uint64 wrap-around of the maximum HP), `num.luau`, `facts.luau`, `consts.luau` (generated from the binary).
* `conformance/golden_gen/golden_status_hook.inc` (+ `enum_statuses.py`, `gen_status_cases.py`, `gen_status_consts.py`): the status hook of the golden generator, see its README. `conformance/golden/status_re.jsonl.gz`:
  the recorded cases. `tests/support/status_runner.luau` replays them; `tools/run_tests.py --status-report` prints the match rate by function, category and status plus the contribution coverage (all 658 sites applied
  by some case, every conditional site also skipped by some case); `tools/status_trace.sh <id>` shows one case; `tools/mutation_status.py` (51 mutants); `tools/status_overlap.py` (PRE against RE, part 2 of the proof);
  `tools/host_status/` replays the golden inside script-host's real mod sandbox (no script-host change needed).

## Run

## Pipeline runtime and legacy_quirks (follow-up to the proof)

`register(engine)` hands the 24 weapon stage bodies to script-host's pipeline runtime and `calc_attack` calls `pipeline.run("weapon", S, ...)`, so mods can insert,
replace, cancel and move stages of this package (`script-host/tests/test_rulesets.cpp` does, and replays the 8,858 golden cases through the real runtime).
`cfg.legacy_quirks` (default true, from the manifest through `engine.config`) governs the doubled monster crit multiplier and the `weapon_damage_rate[16]` aliasing:
see the header of `scripts/damage/weapon.luau` and `tests/acceptance/quirks_test.luau`. Details and numbers: `docs/ARCHITECTURE_PROOF.md` section 12.
